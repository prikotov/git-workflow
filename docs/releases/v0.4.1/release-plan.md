# План релиза v0.4.1

## Метаданные

- Тег релиза: `v0.4.1`
- Тип повышения версии: `patch`
- Обоснование выбранной версии: совместимое исправление документации — словарь терминов переведён с HTML-якорей на чистый Markdown (один термин — один файл), ссылки на термины стали файловыми; поведения кода и контрактов init-скрипта не изменилось
- База рабочей ветки: `master` (`322db83e`)
- Рабочая ветка: `release/0.4.1`
- PR подготовки релиза в основную ветку: [#13](https://github.com/prikotov/git-workflow/pull/13)
- Ответственный: владелец проекта
- Плановая дата публикации: 2026-09-22

## Состав

- Включённый PR: [#12](https://github.com/prikotov/git-workflow/pull/12)
- Включённая задача: [TASK-fix-glossary-pure-md-anchors](../../../todo/done/TASK-fix-glossary-pure-md-anchors.todo.md)
- Словарь терминов: `glossary.md` (26 HTML-якорей `<a id>`) → каталог `glossary/` из 26 файлов терминов + обзорный `index.md`
- Ссылки на термины стали файловыми (`glossary/deployment.md` вместо `glossary.md#deployment`): читаемы в исходнике и URL, стабильны к переформулировкам, переименования отслеживаются git'ом
- Обновлены точки входа: оглавление `index.md`, `release.md`, `README.md`, `AGENTS.md`

## Риски

- Меняются URL-якори терминов словаря: внешние глубокие ссылки вида `glossary.md#…` перестанут работать; внутри пакета все ссылки обновлены.
- Проекты-потребители, сканирующие скопированную документацию валидатором ссылок, получают зелёную проверку без исключений для глоссария.
- Миграции данных и переменных окружения отсутствуют.

## Порядок публикации

1. Слить PR из `release/0.4.1` в `master` после успешного CI и одобрения.
2. Проверить совпадение содержимого одобренной ветки и коммита слияния.
3. Создать и отправить аннотированный тег `v0.4.1` на проверенный коммит слияния.
4. Создать GitHub Release по существующему тегу.

## Проверки перед публикацией

- `composer validate --strict`
- CI репозитория успешен
- Проверка относительных Markdown-ссылок (`validate-md-links` из prikotov/coding-standard v0.33.0) и `git diff --check`
- Тег и ветка выпуска до начала подготовки свободны

## Проверки после публикации

- GitHub Release `v0.4.1` опубликован и указывает на ожидаемый SHA.
- Composer VCS metadata видит тег `v0.4.1`.
- `bin/git-workflow-init` из установленной версии копирует каталог `glossary/` в тестовый каталог.

## Действия при проблеме после релиза

- Откат не используется; опубликованный тег не изменяется.
- Исправление выпускается новой patch-версией из тега `v0.4.1`.
- Координация: GitHub Issue и задача в `todo/`.
