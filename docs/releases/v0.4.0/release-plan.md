# План релиза v0.4.0

## Метаданные

- Тег релиза: `v0.4.0`
- Тип повышения версии: `minor`
- Обоснование выбранной версии: публичный workflow пакета несовместимо изменён в серии `0.x`: каждый выпуск теперь использует отдельную ветку `release/x.y.z`, а hotfix готовится через отдельную целевую релизную ветку
- База рабочей ветки: `master` (`6530aa1`)
- Рабочая ветка: `release/0.4.0`
- PR подготовки релиза в основную ветку: будет указан после создания PR
- Ответственный: владелец проекта
- Плановая дата публикации: 2026-09-16

## Состав

- Включённый PR: [#10](https://github.com/prikotov/git-workflow/pull/10)
- Отдельные ветки `release/x.y.z` для каждого выпуска, включая patch
- Уточнённый обычный и hotfix-процесс, проверка SHA и неизменяемость опубликованных тегов
- Отдельный шаблон плана hotfix и словарь терминов workflow
- Универсальное определение основной ветки через `origin/HEAD`

## Риски

- Проекты, копирующие документацию пакета, должны перейти с общих веток `release/x.y` на отдельные `release/x.y.z`.
- Composer-ограничение `^0.3` не установит `v0.4.0` автоматически; потребителям потребуется явное повышение ограничения.
- Миграции данных и переменных окружения отсутствуют.

## Порядок публикации

1. Слить PR из `release/0.4.0` в `master` после успешного CI и одобрения.
2. Проверить совпадение содержимого одобренной ветки и коммита слияния.
3. Создать и отправить аннотированный тег `v0.4.0` на проверенный коммит слияния.
4. Создать GitHub Release по существующему тегу.

## Проверки перед публикацией

- `composer validate --strict`
- CI репозитория успешен
- Проверка относительных Markdown-ссылок и `git diff --check`
- Тег и ветка выпуска до начала подготовки свободны

## Проверки после публикации

- GitHub Release `v0.4.0` опубликован и указывает на ожидаемый SHA.
- Composer VCS metadata видит тег `v0.4.0`.
- `bin/git-workflow-init` из установленной версии копирует новые шаблоны и словарь в тестовый каталог.

## Действия при проблеме после релиза

- Откат не используется; опубликованный тег не изменяется.
- Исправление выпускается новой patch-версией из тега `v0.4.0`.
- Координация: GitHub Issue и задача в `todo/`.
