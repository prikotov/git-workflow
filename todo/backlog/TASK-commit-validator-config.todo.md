# TASK-commit-validator-config: Конфигурируемость validate-commit: типы черновых коммитов, футеры тела и регистр subject

## 1. Concept and Goal (Концепция и Цель)

### Контекст (от потребителя пакета)
Проект-потребитель stocks2 (Symfony 8 / PHP 8.4) использует `bin/validate-commit` (v0.4.2, `Parser` из `ramsey/conventional-commits` 1.7.0) как commit-msg hook. Многоэтапная работа AI-агентов требует промежуточных/черновых коммитов; хук отклоняет их и тела с внутренними ссылками на PR. Три ретроспективы потребителя + свежий конвейер зафиксировали повторяющиеся отказы; исполнители вынуждены изобретать обходы (тип `feat/chore` с пометкой «черновик», тире вместо двоеточия).

### Goal (Цель по SMART)
Сделать `validate-commit` конфигурируемым через файл конвенций проекта (`.commit-conventions.json`) в трёх точках ниже, без ослабления валидации финальных коммитов по умолчанию.

## 2. Verified Facts (Проверенные факты по коду v0.4.2)

Проверено по `bin/validate-commit` и vendor-коду `ramsey/conventional-commits` 1.7.0 (эмпирика + исходники):

1. **Типы черновиков конфигом не включаются.** `new Parser()` создаётся без конфигурации (`validate-commit:227`); список типов — захардкоженная константа `VALID_TYPES` (`validate-commit:58`, проверка `isset` на :253). Собственный `.commit-conventions.json` читается только на `scopes`/`examples` (`:182`, лишние ключи пропускаются `array_merge`-ом без использования). Ключ `extra.ramsey/conventional-commits` в composer.json этим скриптом не читается (его читают консольные команды ramsey/CaptainHook).
2. **Тело с `PR #N:` отклоняется.** `PR` в теле открывает футер (`tokenPrefix = <noun>(": | #(?=\w))`), далее `123:` парсится как следующий футер с пустым значением → `Footer values may not be empty.` Эмпирически подтверждено.
3. **Регистр subject — только латиница.** `preg_match('/^[A-Z]/', $subject)` (`validate-commit:279`): `chore(task): Test subject` → отказ (exit 1), `chore(task): Тест subject` (кириллическая заглавная) → проходит. Для русскоязычных коммитов потребителя правило фактически не срабатывает.
4. **Инсталлятор `git-workflow-init` не перезаписывает существующие доки** без `--force` — обновлённая документация пакета не доезжает до установленных копий автоматически (см. часть 3).

## 3. Requirements (Требования, MoSCoW)

### 🔴 Must Have (Обязательно)
- [ ] **Часть 1 — ключ `types` в `.commit-conventions.json`:** возможность добавить типы черновиков (например `wip`, `draft`) к базовому набору; `validate-commit` пробрасывает конфигурацию в `Parser` (или фильтрует до него). По умолчанию поведение не меняется (типы по умолчанию — как сейчас).
- [ ] **Часть 2 — документация тела/футеров:** в `docs/git-workflow/commits.md` зафиксировать границы футеров (паттерн `<noun>:` / `<noun> #digit` в теле) и легальные обходы для ссылок на PR: `PR #N — текст`, `(#N)`, футер `Refs: #N`. Все три подтверждены эмпирикой на v0.4.2 как проходящие.
- [ ] **Часть 3 — регистр subject:** либо расширить проверку до Unicode (`/^\p{Lu}/u`), либо явно задокументировать, что правило действует только для латиницы (сейчас в доке пакета — безусловное «со строчной буквы»).
### ⚫ Won't Have (Не будем делать)
- [ ] Ослабление валидации финальных коммитов по умолчанию; форки ramsey; override-классов вендора в потребителях; обязательное включение черновых типов во всех потребителях (только опционально конфигом).
