# TASK-document-semver-zero-major: Уточнить выбор версии для несовместимых изменений в 0.x

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

Правило `major — breaking changes` не учитывает начальную разработку по Semantic Versioning: версия `0.y.z` не объявляет публичный API стабильным. Из-за этого единичное несовместимое изменение ошибочно трактуется как обязательный переход на `1.0.0`.

### Варианты или путь решения (Solution Sketch)

Закрепить распространённую конвенцию для `0.x`: несовместимость повышает `minor`, явно отмечается в CHANGELOG и плане релиза, а `1.0.0` публикуется при объявлении публичного API стабильным.

### Ожидаемый результат (Expected Result)

Гайд, чеклист и единый распространяемый шаблон плана релиза дают одинаковые правила выбора версии.

## 1. Требования (Requirements)

- [x] В `release.md` описана матрица `patch` / `minor` / `major` отдельно для `0.x` и стабильных версий.
- [x] Связь с Conventional Commits учитывает `BREAKING CHANGE` и `!` для `0.x`.
- [x] Чеклист требует обосновать версию и явно документировать несовместимость.
- [x] Единый шаблон плана релиза содержит тип повышения и его обоснование.
- [x] Дублирующая копия шаблона удалена, все ссылки ведут на канонический файл.

## 2. Критерии приёмки (Definition of Done)

- [x] Несовместимое изменение `0.Y.Z` ведёт к `0.(Y+1).0`.
- [x] Несовместимое изменение начиная с `1.0.0` повышает `major`.
- [x] Первый стабильный `1.0.0` не создаётся автоматически из-за несовместимости.
- [x] `composer validate --strict` выполняется успешно.
- [x] Init smoke (дымовая проверка инициализации) подтверждает копирование обновлённых документов.

## 3. Источники (Sources)

- Semantic Versioning 2.0.0: https://semver.org/spec/v2.0.0.html
- Запрос владельца проекта: принять общепринятый Semantic Versioning для релизов `0.x`.
